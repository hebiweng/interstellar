## 1. 计划定位与优先级

本文件是 iOS V1 的执行合同，负责约束开发顺序、架构边界、验收证据和需求变更。

优先级从高到低为：

1. 本文件中的“冻结产品合同”；
2. 本文件中的开发阶段、门禁和停止条件；
3. 已批准的 iOS ADR；
4. 当前阶段任务清单。

[`project-plan.md`](./project-plan.md)和[`natal-development-plan.md`](./natal-development-plan.md)继续约束 Web、后端和专业本命盘工作，不得用其中“只开发本命盘”或“不开发原生移动应用”的规则阻止本文件授权的 iOS 工作。本文件也不授权修改 Web 产品范围、HTTP API 或服务端路线。

开发计划可以调整实现顺序，但不得自行改变产品范围。改变盘型、用户流程、计算语义、发布门禁或离线边界，必须先修订本文件。

## 2. 冻结产品合同

### 2.1 首版必须实现

- 原生 iPhone 应用，SwiftUI，最低 iOS 17，竖屏优先；
- `Today / Charts / Ask / Profile` 四栏导航；
- 本命盘（Natal）；
- 当前天象盘（Current Sky）；
- 行运盘（Transits）；
- 次限盘（Secondary Progressions）；
- 每个已实现盘型提供 `Wheel / Aspects` 两种视图；
- 本命、天象使用单轮；行运、次限默认使用本命内轮与动态外轮；
- 每个盘型的消费者界面只保留 Modern、Classical 两个预设；比较盘的移动盘与本命参照必须使用同一所选预设；
- 本人资料及本地人物资料库；其他人物必须记录与本人的关系；
- 本人和其他人物头像；
- 默认地点、Apple 地图搜索/点选、当前位置、反向地理编码、自动时区和可编辑经纬度；
- 本地计算、本地保存、本地 Today 日内事件搜索；
- 简洁英文界面和版本化英文解析内容；
- 计算事实与原创语料分离。

### 2.2 Today 的产品定义

Today 不是四张盘的缩略页。本命盘提供个人基线，Today 从天象、行运和次限中筛选所选地点自然日内真正发生或仍然有效的变化。

Today 必须：

- 按所选地点时区的本地自然日计算；
- 正确处理夏令时导致的 23 小时或 25 小时自然日；
- 最多展示五条信号，不足五条时不得填充；
- 分为 `Happening Today` 和 `Active Now`；
- 支持精确相位、进入/离开容许度、换座、换宫和顺逆行变化；
- 优先排列今日精确、今日边界变化、仍在生效的紧密信号；
- 不显示不透明的好运分、风险分或综合概率；
- 点击信号后打开对应盘型、时刻和相位上下文；
- 无本命资料时仅展示当前天象与建档引导。

#### 2.2.1 Today 消费者呈现（2026-07-29 冻结）

Today 不按四张盘分区，不把参数或专业术语作为首屏主体。四张盘是解释依据，消费者看到的是：

1. 今日主线：一句明确、通俗的个人结论；
2. 今日节奏：仪表弧与日内波形，展示上午、下午、晚间的相对变化；
3. 四个固定生活领域：感情与关系、事业与方向、财富与资源、精力与状态；
4. 四领域雷达与领域卡片：只表达平稳、活跃、拉扯等可读状态，不显示伪造概率或好运分；
5. 接下来节奏：由真实 `DailySignal` 去重后生成的整体氛围、个人节奏与长期变化视觉轨道，不直接展示重复的星体主题短语；
6. 本周七天综合进展：位于 Today 最底部，显示节奏变化、最忙节点是否已过及下一重点；不得按盘型分组。

Today 不显示“四盘依据”“今日解读的依据”或盘型参数。四盘只在内部作为标准信号来源。

Today 的视觉语言复用 Obsidian 已有的仪表盘、波形、雷达、环形结构和时间线，不新造另一套设计系统。

消费者文案必须：

- 从项目内私有 corpus / rules 选择，运行时不得读取 Obsidian；
- 使用日常语言，不出现“信号密度、承载、联动、映射、模板回答”等内部话术；
- 不把“解释图表含义”“不是预测”“需结合本命盘”等编写说明改写成卡片正文；
- 不为了达到约 100 字而填充空话；摘要能独立传达结论，详情只补充实际含义；
- 专业相位、容许度、入相/出相等精确事实只进入轮盘与相位矩阵；消费者摘要、详情与 Today 必须转换为明显程度、增强/缓和、生活领域等日常表达；
- 不硬编码当前示例人物的特定数值或结论。

### 2.3 首版明确不做

- 合盘计算、Composite、Davison、Dynamic Relationship；
- 原型中的 `Relationship context`；
- 除本计划单列的 Ask 问事盘外，不做返照、太阳弧、三限或其他盘型；
- 不精确出生时间模式；
- 专业参数、自定义容许度或任意点位配置；
- 账号、云同步或服务器计算；
- Web Today、后端事件搜索 API 或现有 Web 重构；
- 专业数据包下载；
- StoreKit、订阅、远程授权或远程 DRM；
- AI 解读；
- 未经用户再次授权的 App Store 提交。

### 2.4 Ask the Chart 产品定义（2026-07-30 冻结）

Ask 替代原 `Synastry` 底部入口，但不加入现有四盘 `ChartKind`。它是独立问事会话，复用星历事实与基础单盘渲染器。

必须包含：

- `Will It Happen?`：具体问题、目标生活领域、起盘时刻地点，输出答案、可追溯的可能性、消费者卡片和专业分析；
- `Which One?`：默认两个、最多五个实际选项；每项必须映射不同生活领域，输出总计 100% 的归一化可能性与完整排名；前两项相差不超过 8 个百分点时显示结果接近；
- `Find the Best Time`：目标领域、可选行动名称、日/周/月精度与范围，输出第一推荐和两个备选；适合度互不要求加总，周/月同时显示峰值日；
- 问事轮盘高亮相关宫位、代表星与关键相位；专业页展示相位矩阵、宫主星、力量、接纳、月亮状态和评分拆解；
- 日精度最长 90 天、周精度最长 6 个月、月精度最长 12 个月；分层扫描必须可显示进度并取消，不阻塞主线程；
- 首版不保存问事历史。

问事计算固定使用 Regiomontanus、传统七曜、传统守护关系、五大相位、入相/出相、庙旺落陷、宫位力量、接纳、逆行、燃烧、Cazimi、月亮下一相位与空亡。消费者界面使用十二类生活领域，不显示宫位编号；宫位编号仅进入专业分析。

百分比必须由评分构成计算，不得使用示例分数。Ask 正文通过少量版本化私有内容键组合；计算事实、排名和评分拆解不写成大规模固定语料。

### 2.5 可读性、字体与反馈

- 消费者正文不低于 13pt；核心摘要以 15—17pt 为基准；9pt 及以下只允许用于轮盘内部极短辅助标记；
- 使用系统语义字号与 Dynamic Type，设置提供 Small / Standard / Large / Extra Large，卡片允许增高、换行和滚动；
- 大屏设备必须同步放大轮盘文字、度数和标注，拥挤通过引线、错位和分层解决；
- 详情、加号、选项和专业分析入口的点击区域不得小于 44pt；
- Settings 提供 Report，分类固定为 Bug / Feature / Other；
- Report 是除 MapKit 外唯一允许的主动网络提交入口，只发送用户填写的反馈、可选联系方式和基础设备版本信息，不得附带出生资料、盘面或私有语料；失败时允许复制内容。

## 3. 强制架构约束

### 3.1 离线与网络

- iOS 只能调用本地 `AstroCore`，不得把 HTTP API 作为主路径、降级路径或校验后备；
- MapKit 地点搜索与用户主动提交 Report 是唯二允许的在线辅助；
- 用户点击选址即视为定位授权动作：组件请求当前位置并打开 Apple 地图，同时允许搜索和点选；
- 保存地点后，人物、四盘、Today 和解析必须可在飞行模式运行；
- 不新增账号、遥测、远程配置或隐藏网络调用；Report 不得静默发送。

### 3.2 计算事实

- React、TypeScript 和 Python 代码不嵌入 App；只复用计算语义、预设定义和测试夹具；
- Swiss Ephemeris 通过本地 C Target 或等价的可审计本地桥接接入；
- 四盘共享时间、地点、点位、宫位、相位、快照和渲染模型；
- 计算结果采用不可变 Snapshot；视图状态与计算状态分离；
- Wheel / Aspects 切换不得重新计算；
- 同一输入、预设、核心版本和数据版本必须产生可复现结果；
- 复杂算法先固定公式、输入、输出和黄金样例，再写生产实现；
- 未验证事实不得通过改名、隐藏警告或模拟数据进入稳定界面。

### 3.3 预设

全局消费者界面只提供两个版本化预设：

- Modern：Tropical + Placidus，十颗行星、ASC/MC、True Node、Mean Lilith、Fortune、Juno 和五大主要相位；
- Classical：Tropical + Alcabitius，传统七曜、ASC/MC、True Node、Fortune 和古典星光容许度；

天象继承全局预设。行运和次限继承对应点集和宫位体系，但自动采用动态盘紧容许度规则。首版不得为四盘分别保存互相冲突的预设。

高纬度无法计算 Placidus 或 Alcabitius 时不得静默改用其他宫制；必须明确显示原因。旧版本的 `Special` 只保留为持久化数据解码兼容值，并在读取时迁移为 Modern，不能出现在首版界面。

### 3.4 解析内容与版权

- 事实模型只保存 `contentKey`，不得内嵌完整私有解析；
- 公共仓库只包含内容 Schema、验证器和少量英文样例；
- 完整原创语料由私有构建产物注入官方 App；
- 私有内容包缺失、规则缺失或必需语料无法匹配时，盘面计算仍可用，但该盘解读必须明确显示内容不可用；不得用通用事实句或重复套话伪装成正式解读；
- 关系标签、解释视角或语料选择不得改变天文事实；
- 日志、崩溃信息、测试附件和 Git 历史不得包含完整出生资料或私有语料；
- App 内加密只视为普通提取防护，不宣称无法破解。

### 3.5 本地模块与接口

目标模块：

- SwiftUI App：导航、页面、状态、深链和无障碍；
- AstroCore：Swiss Ephemeris 桥接、四盘计算与 Today 事件引擎；
- Horary/Election：独立问事会话、问事评分、择时扫描与轮盘覆盖层，不污染四盘 `ChartKind`；
- ChartRenderer：单轮、双轮和相位矩阵；
- DataStore：单人物、偏好、快照与 Today 缓存；
- LocationKit：MapKit、Core Location、时区和手动地点；
- ContentKit：内容 Schema、样例包和私有内容包加载。

### 3.6 轮盘与相位图视觉约束

- `Aspects` 必须以相位矩阵呈现：单盘使用三角矩阵，行运/次限使用移动点 × 本命点交叉矩阵；
- 轮盘在保持 iPhone 可读的前提下增加 1°/5°/10° 刻度层级、十二宫编号、ASC/MC/DSC/IC 轴线、星体度数引线和逆行状态；
- 双轮必须清楚区分本命内圈与动态外圈，并保留跨盘相位连线；
- 星座环、宫位环、星体环、相位区和中心信息必须形成明确层级；
- 不以增加复杂度为由堆叠无法辨认的文字；拥挤时优先使用引线、错位排布和展开详情。

冻结以下本地接口语义：

- `ChartCalculationService`
  - `calculateNatal`
  - `calculateCurrentSky`
  - `calculateTransit`
  - `calculateSecondaryProgression`
- `DailyEventSearchService`
  - 输入日期、时区、地点、本命快照和预设；
  - 输出 `DailyDigest` 和排序后的 `DailySignal`；
- `ContentKit`
  - 根据不可变盘面事实建立 `InterpretationContext`；
  - 根据稳定语义 ID、语言、selector、优先级与 composition rules 生成摘要和详情；
  - Release 只加载 `approved`，Debug 可显式加载 `sample`；
- `LocationProvider`
  - 管理默认地点、地点搜索和用户主动定位；
- `EntitlementProvider`
  - 首版只提供本地默认实现，不得引入服务器依赖。

冻结的公共类型包括：

- `ChartKind`
- `ChartViewMode`
- `CalculationPreset`
- `ChartSnapshot`
- `ChartComparison`
- `DailyDigest`
- `DailySignal`
- `CalculationWarning`
- `ContentKey`

现有 HTTP API 和 TypeScript SDK 不属于本计划的修改范围。

## 4. 开发阶段与门禁

阶段严格按 `IOS0 → IOS7` 推进。阶段内部可以使用契约 Mock 并行开发，但阶段出口必须连接真实本地实现。

### IOS0：计划冻结与技术验证

交付：

- 固化本计划、能力清单、公共类型和排除项；
- 安装并验证完整 Xcode、iOS 17 SDK、模拟器和签名环境；
- 建立最小 App 工程与本地 Swift Package；
- 将 Swiss Ephemeris 编译进模拟器和真机目标；
- 完成太阳、月亮、ASC、MC 的最小计算验证；
- 核查 AGPL、Swiss Ephemeris 和星历数据的分发要求。

出口：

- 模拟器和至少一台真机能够构建运行；
- 最小计算结果通过 Python 参考夹具；
- 许可和数据来源没有未解决的发布阻塞；
- IOS0 通过前不开发正式功能页面。

### IOS1：应用骨架、人物与地点

交付：

- 四栏 SwiftUI 导航；
- Profile 单人物创建、编辑和设置齿轮；
- 精确出生时间、地点、IANA 时区和经纬度输入；
- 默认地点、MapKit 搜索、手动地点和主动定位；
- SwiftData 人物、偏好与缓存模型；
- 两个消费者预设；
- Ask 替代原 Synastry 入口；Relationship context 与合盘计算仍不进入首版。

出口：

- 重启应用后人物和设置正确恢复；
- 拒绝不存在的当地时间和缺失的精确出生时间；
- 地点搜索不可用时可手动完成资料；
- 不产生服务器计算请求。

### IOS2：本命盘纵向切片

交付：

- 本命点位、宫位、主要相位和两个消费者预设；
- 单轮、标签避让、相位线和相位矩阵；
- 简洁事实卡与样例英文解析；
- 高纬度、星历缺失和输入错误提示。

出口：

- 点位黄经差异不超过 `0.0001°`；
- 宫头差异不超过 `0.001°`；
- 相位容许度差异不超过 `0.001°`；
- 两个消费者预设均有黄金测试；内部兼容枚举不得出现在界面；
- Wheel / Aspects 切换不重新计算。

### IOS3：当前天象纵向切片

交付：

- 指定时刻和地点的 Current Sky；
- 单轮、天象相位矩阵和简洁解析；
- 默认使用当前时间与默认地点；
- 无本命资料时可供 Today 使用的天象数据。

出口：

- 当前、历史和夏令时边界时刻通过参考测试；
- 无人物资料也可以独立使用天象盘；
- 飞行模式可使用已保存地点重新计算。

### IOS4：行运纵向切片

交付：

- 指定时刻的移动星体与本命比较；
- 本命内轮、行运外轮、跨盘相位及矩阵；
- Today 信号到指定行运时刻和相位的深链。

出口：

- 双轮和跨盘相位来自同一次不可变结果；
- 0° 边界、逆行和入出相测试通过；
- 无本命资料时明确阻断，不生成示例结果。

### IOS5：次限纵向切片

交付：

- 标准一日一年法；
- 次限自身事实、与本命双轮比较和跨盘相位；
- 目标日期默认今天，首版固定使用出生地点；
- 次限事实卡和少量英文样例解析。

出口：

- 出生当日、闰年、时区和长期跨度测试通过；
- 推进时刻和点位与 Python 结果一致；
- 不允许目标日期早于出生日期；
- 未验证派生事实不得进入界面。

### IOS6：Today 日内变化引擎

交付：

- 按本地自然日扫描天象、行运和次限；
- 检测精确相位、容许度边界、换座、换宫和运动方向变化；
- 每 60 分钟粗采样，事件区间求精至 60 秒以内；
- 检查逆行转向附近的局部极值，避免遗漏触碰型事件；
- `Happening Today`、`Active Now`、最多五条、稳定排序和事件去重；
- 自动计算、版本化缓存和盘面深链；
- 无本命资料时显示天象和建档引导。

出口：

- 23/25 小时自然日正确；
- 359°/0°、多次精确经过、容许度边界和无事件日期通过黄金测试；
- 不足五条时不填充；
- 普通目标设备冷计算不超过 2 秒；
- 缓存命中不超过 200 毫秒；
- Today 不调用后端 API。

## 5. Today 事件搜索约束

Today 事件引擎只在 iOS 本地实现，不修改后端 HTTP API。

算法基线：

- 使用时区中的当地午夜生成起止 UTC，不假定一天固定为 24 小时；
- 天象和行运按绝对时间每 60 分钟粗采样；
- 对相位精确、容许度边界、黄经边界、宫头边界和速度过零建立区间；
- 使用二分或割线方法求精，时间误差不超过 60 秒；
- 检查局部极小值，处理逆行转向附近没有简单符号翻转的情况；
- 次限使用同一事件模型，但允许针对慢速变化减少重复星历计算；
- 本命只提供静态目标，不产生“本命今日变化”；
- 同一事件按技法、事件类型、点位、相位、日期和经过序号生成稳定 ID；
- 多次精确经过分别保留；
- 事实排序不依赖原创语料；
- `DailySignal` 只持有事实、时间、状态、深链和 `contentKey`。

缓存键至少包括：

- 当地日期；
- 时区；
- 地点坐标；
- 人物资料哈希；
- 全局预设版本；
- AstroCore 版本；
- Swiss Ephemeris/数据版本。
