# Interstellar 本命盘优先开发计划

| 字段 | 值 |
|---|---|
| 文档版本 | 1.3.1 |
| 生效日期 | 2026-07-19 |
| 当前交付目标 | 专业本命盘完整产品闭环 |
| 执行原则 | 保留全项目信息架构，只实现本命盘；本命盘完成后停止，不自动恢复其他技法 |
| 主要用户 | 职业占星师、占星学习者、重度爱好者 |

> **适用范围说明：** 本文件只约束 Web、后端和专业本命盘产品闭环，不约束 `ios/**`。原生 iOS 的执行依据为 [iOS v6 重构执行合同](./ios-v6-rebuild-plan.md) 和 [卡片实施矩阵](./ios-card-implementation-matrix.md)。iOS 计划不反向授权 Web 开发行运、天象或次限。

## 1. 当前决策

原 M0—M24 路线不再作为当前自动执行序列。它保留为未来能力目录和长期参考，但当前开发只推进本文件定义的 `N0—N8`。

本轮不是把 Interstellar 缩减为“只有本命盘的网站”，而是：

- 保留工作台、分析中心、技法排盘、独立对象库和未来图表能力；顶部不再保留独立“报告”入口；
- 保留本命、行运、天象、次限、三限、太阳弧、返照、关系、卜卦、地理等未来入口；
- 本命盘是当前唯一完整可运行的技法；
- 未实现技法只展示用途、输入、输出和“规划中”，不得复用本命结果或弹出相同假功能；
- 完成本命盘后停止，等待用户明确决定下一项技法。

### 1.1 当前发布与账户决策（2026-07-19）

- 顶部不再展示“VIRTUAL FIXTURE／静态虚拟验收样例”通知条；默认演示人物仅在人物卡内透明标记为非真实资料。
- 登录入口使用站内弹窗，提供邮箱密码注册、登录和退出；密码使用`scrypt`加盐哈希，会话使用随机令牌且服务端只保存令牌哈希。
- 游客可以新增临时人物、完成计算和提交可用的AI分析，但人物、计算与AI文本不持久化。
- 注册用户按账户隔离人物；每个人物只保存最后一次本命盘及其参数、分析文档和AI响应，重新计算原子覆盖旧结果。
- 生产域名固定为`fate.xiaoguiwk.top`。前端、FastAPI、账户SQLite和反向代理作为独立Interstellar服务部署，不经过或复用Ledger项目出口。
- 当前地点选择继续使用现有城市/地区候选，不在本轮扩展。未来可通过GeoNames `allCountries`、行政区代码和合规OSM数据补充区县、乡镇与历史别名；街道/门牌级可靠地理编码需另行评估商业服务、许可与运维成本。

### 1.2 对象、分析与后台决策（2026-07-19）

- 顶部导航固定为“工作台 / 分析中心 / 技法排盘 / 对象库 / 新建分析 / 账户”；删除“报告”和“计算方法”。
- `对象库`使用独立页面，不与用户中心合并。用户中心只承载账户、安全、隐私、偏好和对象快捷入口。
- 本命首发先完整支持人物对象；关系、事件、项目、组织、地点和问题/案例使用强类型对象逐步启用，未实现类型不得打开人物表单或假计算。
- `新建分析`采用“选择内容 → 选择/新增对象 → 推荐方案与关键参数 → 生效预检 → 计算”的五步流程。
- 推荐方案必须显示适用场景、版本和来源，只能称“平台推荐”“常用配置”或明确的流派方案，不宣称行业唯一权威。
- 新增独立`/admin`后台。首发角色只有`user/admin/super_admin`，支持用户状态、会话撤销、用量/行为聚合、管理员和平台API Key管理；暂不做用户级细粒度权限和套餐额度。
- 详细数据模型、接口、状态机和验收见[`admin-object-analysis-plan.md`](./admin-object-analysis-plan.md)。

## 2. 竞争标准

本命盘在信息维度、可调参数、图形、基本解析和古典解析上不得少于用户提供的竞品样本。可以采用不同的信息架构、视觉语言和实现方式，不复制竞品文本、专有评分、来源不明公式或界面。

验收采用三层口径：

1. **确定性事实不减项**：竞品展示且有公开、可验证算法依据的字段，Interstellar 必须计算或明确说明阻塞原因。
2. **专业表达不减项**：竞品可查看的盘、相位表、基础表和古典表，Interstellar 必须有等价或更强的视图。
3. **可追溯性必须超越**：每项结果附算法/规则方案、数据版本、成熟度、警告和可复现指纹；不适用与未知不得伪装成数值。

详细逐项差距由 [`natal-competitor-gap.md`](./natal-competitor-gap.md) 维护。竞品截图和导出只作为字段覆盖夹具，不作为公式或解释文案来源。

## 3. 用户工作流

### 3.1 默认打开

匿名用户打开网站时：

- 中央展示演示人物本命盘，人物卡明确标记“演示人物 · 非真实资料”，不与用户人物库混淆；
- 顶部保留全局导航和唯一主动作“新建分析”；
- 盘型快捷栏保留未来技法，本命盘高亮，未实现项显示独立说明；
- 左侧对象快捷区只展示当前/最近人物，并可进入独立对象库；
- 中央默认显示本命轮盘；
- 右侧显示本次计算生效的核心参数；
- 下方显示点位、宫位、相位、结构、古典和技术导出视图。

### 3.2 新增人物

“对象库 → 新增人物”只保存人物资料，不触发计算：

```text
姓名/称呼
→ 与我的关系
→ 出生日期与时间精度
→ 搜索出生地点
→ 选择系统返回的 IANA 时区候选
→ 自动得到经纬度和国家/行政区元数据
→ 可选高级人工覆盖经纬度
→ 保存人物版本
```

- 国家代码不参与占星判断，由地点结果派生并默认隐藏；
- IANA 时区禁止自由文本输入；
- 出生地点以城市/乡镇级为默认精度，医院/街道不是必填；
- 不知道出生时间不得补 `00:00`；必须进入未知时间模式并关闭四轴、宫位及其依赖解读。

### 3.3 新建分析

全局右上角“新建分析”只创建分析任务，不负责单独建档：

```text
选择要分析的内容（技法/专题/目的）
→ 选择已有人物，或内联填写临时人物
→ 选择版本化推荐方案
→ 确认分析体系、黄道、宫位制、点集、相位集和容许度等关键参数
→ 预检实际生效参数、降级项、预计输出和保存语义
→ 计算不可变 Snapshot
→ 查看轮盘、表格、逐项解读和技术导出
→ 可选保存临时人物、结果和设置 Preset
```

临时人物默认不进入人物库；“保存为本人/亲友/伴侣/朋友/客户/其他”必须由用户显式勾选。

推荐方案的默认值来自版本化Preset和对应算法卡。方案卡必须解释“为什么推荐、适合什么场景、会生成什么、与其他方案有何差异”；内部ID折叠到技术详情。预检页必须区分必需且锁定、推荐默认、用户覆盖、不可用和降级，并在运行前展示最终生效参数。

## 4. 本命盘专业参数

参数分为三层，避免把数十项设置平铺在一个长弹窗中。

### 4.1 盘旁快捷参数

| 参数 | 默认值 | 改变后是否重算 |
|---|---|---|
| 规则方案 | 专业综合 | 是 |
| 黄道 | 回归黄道 | 是 |
| 宫位制 | Placidus | 是 |
| 点位方案 | 专业 | 是 |
| 相位方案 | 现代主要+常用次要 | 是 |
| 容许度方案 | 现代标准 | 是 |
| 结果视图 | 轮盘 | 否 |

### 4.2 计算设置

- 黄道：回归黄道；恒星黄道（必须选择并显示 Ayanamsa）；
- 宫位：当前直接开放 22 种 Swiss Ephemeris 支持且已通过 12 宫跨度回归的体系：Placidus、Whole Sign、Koch、Porphyry、Regiomontanus、Campanus、Equal、Alcabitius、Topocentric、Morinus、Krusinski、Vehlow、Equal MC、Equal Aries、Meridian/Axial Rotation、Horizontal/Azimuthal、Carter Poli-Equatorial、APC、Pullen SD、Pullen SR、Sunshine/Treindl、Sripati；新增体系仍必须先完成枚举、公式/上游代码、测试和高纬边界，再进入界面；
- 坐标中心：地心为本命默认；日心、拓扑中心作为明确变体，不与普通本命混用；
- 核心天体：太阳至冥王星；
- 轴点：ASC、MC、DSC、IC；
- 节点与月球点：真/平均交点、Lilith 变体、近远地点；
- 常用虚点：Vertex、Anti-Vertex、East Point、Fortune、Spirit 等；
- 小行星/半人马体：按数据可用性和许可分组启用；
- Hamburg TNP：独立分组，显示其特殊计算/文件来源；
- Lots：昼夜公式、规则来源和公式版本必须可见；
- 固定星：独立开关和容许度；
- 相位：主要、次要、谐波、平行/反平行、映点/反映点分组；
- 容许度：按相位、点位类别、本命/跨盘场景分别配置；
- 古典规则：守护体系、三分主星表、界、十度区间、接纳、燃烧范围、昼夜方案；
- 高纬策略：明确报错、切换允许的替代宫制或无宫位模式，不静默更改；
- 未知时间：禁用所有时间依赖项并显示原因。

### 4.3 渲染与导出设置

- Dark 与 Light 是同等受支持的产品主题：保持 Dark 为首次默认，用户覆盖选择保存在本机；两套主题共同通过对比度、可读性、响应式和视觉回归验收；
- 行星、点位和相位线显示开关；
- 行星标签避让、图标/文字、度数精度；
- 星座环、宫位环、界/十度区间层；
- 现代/古典配色、色盲友好、高对比；
- 轮盘方向、ASC/0°白羊起点；
- 相位线颜色、粗细、虚实和按容许度隐藏；
- 相位线默认只绘制主要相位中强度最高的 15%，并显示“已绘制/已计算”数量；用户可改为“按强度前百分比”或“最低强度阈值”，也可关闭“仅主要相位”；完整相位始终保留在结果表和导出中；
- 计算参数和显示参数严格分离：黄道、宫位、点位、相位、容许度改动标记“需重新计算”，图层、点位可见性和相位线筛选必须即时改变轮盘；
- SVG、PNG、PDF、JSON、CSV、Markdown、纯文本导出。

小限、法达、黄道释放、推运步长、返照地点等不属于本命盘参数，必须留在对应未来技法中。

## 5. 规则方案与模型命名

本命盘内置四种版本化规则方案：

| 方案 | 主要用途 | 内容 |
|---|---|---|
| 现代本命 | 现代心理和结构观察 | 现代守护、外行星、主要/常用次要相位、元素模式与结构 |
| 古典本命 | 传统七曜与古典状态 | 昼夜、本质/偶然尊贵、接纳、太阳条件、速度与可见性 |
| 专业综合 | 默认 | 现代事实与古典事实分层并列，不混算成不透明总分 |
| 自定义 | 专家 | 从已验证组件组合并生成新 Preset 版本 |

这些是占星规则方案，不是 GPT、Kimi 等 AI 模型。AI 提供方只在“提交至 AI 分析”面板出现。

## 6. 确定性计算范围

### 6.1 时间与天文上下文

- 原始当地时间、历法、时间精度、时区候选、UTC、JD/TT/UT；
- 历史 UTC 偏移、DST、Delta T、恒星时、黄赤交角、章动/岁差模型；
- 日出日落、昼夜盘、月相、月龄和照明比例；
- 时间和地点可信度、数据版本、来源和警告。

### 6.2 每个天体/点位

- 黄经、黄纬、赤经、赤纬、距离；
- 星座、星座内度分秒、宫位、距宫头距离；
- 黄经/黄纬/赤纬速度；
- 顺行、逆行、停滞或“不适用”；
- 东方/西方、晨星/昏星、与太阳角距、可见性；
- 日核、燃烧、光束下、越界；
- 守护、擢升、失势、落陷、三分、界、面、游走；
- 昼夜、Hayz、喜乐、角续果、速度、太阳条件等后天状态；
- 定位星链、互容、单向/双向接纳。

### 6.3 宫位、相位与结构

- 12 宫头、跨度、宫头星座、古典/现代宫主、宫主落座落宫与状态；
- 截夺和重复宫头（适用宫制才展示）；
- 相位双方、理论角度、实际角距、容许度、容许度百分比、入相/出相、跨星座；
- 平行/反平行、映点/反映点等按所选方案输出；
- 元素、模式、阴阳、半球、象限、角续果统计，同时保留原始计数和权重；
- 群星、大三角、T 三角、大十字、风筝、摇篮、神秘矩形、Yod 等几何格局；
- 行星分布形态、主导行星、最终定位星和循环定位；
- Lots、中点和固定星只在已选择且有可靠规则/数据时进入 Snapshot。

## 7. 本命盘输出与页面结构

### 7.1 首屏

- 对象身份与出生资料摘要；
- 未来技法快捷栏；
- 本命轮盘/相位网格切换；
- 生效参数摘要与“高级设置”；
- 时间/地点/规则警告；
- “查看完整解析”和“复制／导出分析数据”主操作。

### 7.2 轮盘与相位图

- 本命单轮盘是默认；
- 相位网格为同一 Snapshot 的第二视图，不重新计算；
- Dark/Light 只改变 `RenderSpec` 与界面外观，不改变计算配方或 Snapshot；
- 纯本命不称“双盘”；双轮/三轮是未来行运、推运、返照或第二人物叠加的渲染能力；
- 点击行星、点位、宫头、相位线或矩阵单元格，打开同一上下文解读抽屉。
- 轮盘中心不得无条件绘制数百条相位线。默认使用 `主要相位 + 强度前 15%`；筛选只属于 `RenderSpec`，不删除 Snapshot 中的完整相位。

### 7.3 结果视图

| 视图 | 必须展示 |
|---|---|
| 基本 | 十大行星、角点、节点、所选点位，精确度数、宫位、运动状态、局部解读 |
| 星座 | 每个点位落座、星座属性、守护关系、原始事实与分层解读 |
| 宫位 | 宫头、宫主、宫内点位、距宫头、宫主链、局部解读 |
| 相位 | 完整列表、相位矩阵、实际角度、容许度、入出相、局部解读 |
| 结构 | 元素、模式、阴阳、半球、象限、分布形态和格局；定位星等内部派生事实只进入专业 JSON/规则计算，不作为默认用户分析文档章节 |
| 古典 | 先天尊贵、后天状态、昼夜、太阳条件、速度、接纳、互容、Lots |
| 分析数据与导出 | 可供占星师或外部模型继续分析的点位、宫位、相位、分布、格局、古典状态和输入提醒；完整 JSON 独立导出 |

所有 Snapshot 中已经物化的集合必须至少被一个可访问表格、图形或导出消费；不得“算了但用户找不到”。

## 8. 解析与报告

### 8.1 逐项解读

以下事实后提供“解读”按钮：

- 天体/点位本身；
- 点位落星座、落宫位和三者组合；
- 运动状态；
- 宫头和宫主链；
- 本命相位；
- 结构指标和格局；
- 古典尊贵、接纳、太阳条件及后天状态。

解读返回：事实、关键词、基础含义、现代层、古典层、当前上下文、反向/限制因素、规则来源、版本、成熟度和警告。没有规则模板时显示“尚未发布解读”，不得使用通用套话或隐式 AI 兜底。

### 8.2 本命综合解析

综合解析至少分为：

- 基本：核心三要素、个人行星、社会/世代行星、元素模式、宫位重心、主要相位和结构；
- 古典：命主星、昼夜、先天尊贵、后天状态、接纳链、主要 Lots 和传统证据；
- 分析数据：只聚合用户可继续分析的计算事实和输入提醒，不混入结果路径、Manifest、内部证据对象、内容哈希或定位星链等开发字段。

综合解析只聚合已有逐项证据，不制造单一“好坏总分”，不输出科学上不可证实的事件概率。

## 9. 复制、导出与 AI 预留

同一不可变 Snapshot 生成一份用户分析文档，并把完整快照 JSON 作为独立专业导出，支持：

- 一键复制 Markdown；
- 下载 `.md` / `.txt` / `.json` / `.csv`；
- 后续生成 PDF；
- 用户自行粘贴给外部模型；
- 部署方配置后提交到 GPT、Kimi 等可选提供方。

用户文档使用 `interstellar.natal.analysis-document.v2`。Markdown与纯文本只改变表现格式，不改变文档语义；复制、下载和 AI 载荷必须来自同一用户投影。该投影禁止出现 `output_manifest`、JSON Pointer/结果路径、Rule Pack 哈希、输入指纹、内部结构化证据、定位星链和原始高级对象。服务端仍以内部哈希保证同一 Snapshot 投影一致，但产品界面不展示这些开发审计字段。完整 JSON 通过单独按钮导出，供有需要的专业人员或故障排查使用。

“提交至 AI 分析”必须先显示提供方、精确模型、发送字段、地区/目的地、隐私与保留说明，并取得逐次同意。未配置模型显示禁用原因。AI 默认只读取用户分析文档，不读取开发审计对象，也不得计算或覆盖星历、星座、宫位、相位和古典事实。

标准部署默认没有配置第三方模型。GPT/OpenAI与Kimi/Moonshot只是允许部署者实现的适配器家族，不是已经接通的服务。即使没有API，用户也必须可以预览将发送的准确载荷、复制和下载分析文档。提交前同时确认“有权提交该人物资料”和“同意发送本次预览的同一载荷哈希”；提供方、精确模型、重点、格式、保存选择或文档改变后，旧同意立即失效。AI响应保存为独立产物，不得写回不可变Snapshot。

## 10. 可复用能力

本命盘阶段必须按可复用模块实现，未来其他盘只组装而不复制：

- `TimeSpec`、地点/时区解析、可信度与未知时间降级；
- Swiss Ephemeris/JPL 适配和统一坐标对象；
- 天体/点位注册表；
- 宫位、相位、容许度、结构和古典状态引擎；
- `RulePack`、Preset、算法卡和版本指纹；
- 不可变 `CalculationSnapshot` 与 `OutputManifest`；
- 轮盘、相位矩阵、专业表格和上下文检查器；
- 逐项解读协议、用户分析文档序列化器和 AI 提交协议；
- 导出、缓存、错误/警告、测试夹具和可访问性组件。

## 12. 测试与完成定义

每项能力必须同时满足：

1. Schema、算法卡、规则来源和默认参数存在；
2. 公式单元测试、边界/属性测试通过；
3. 金标准或独立实现差异验证通过；
4. 竞品字段夹具证明“不减项”或登记明确阻塞；
5. 页面、可访问表格和导出至少有一个消费路径；
6. 逐项解读有版本化规则，或明确显示未发布；
7. 结果附引擎、数据、Rule Pack、输入指纹、成熟度和警告；
8. 桌面与移动端可正常滚动，正文和表格字号可读，弹窗不截断；
9. 设置变更只在必要时重算，视图切换不重算；
10. 构建、契约、回归和端到端流程通过。

竞品存在但公开数据、许可证或权威公式不足的能力，不得捏造。它必须以“待研究/待数据/待授权”保留在差距矩阵中，并说明为何不能安全实现。

## 13. 本轮明确不做

- 行运、天象、次限、三限、太阳弧、返照、关系、卜卦、择时、地理的真实计算与报告；
- AI 自动生成或自动提交；
- 八字、紫微、奇门和印度占星；
- CRM、支付、咨询市场和原生移动应用；
- 用不透明分数替代专业事实；
- 完成本命盘后自动恢复 M0—M24。
