## 1. 项目摘要

> **iOS 适用范围：** 本文当前执行指令约束 Web、后端、API 和专业平台工作，不约束 `ios/**`。原生 iOS V1 已由用户单独授权本命、天象、行运、次限和 Today，其范围、门禁与停止条件以[iOS V1 开发计划](./ios-v1-development-plan.md)为唯一执行依据。iOS 授权不自动扩大本文的 Web 或服务端范围。

> **当前执行指令（优先于本文后续 M0—M24 路线）：** 项目保留完整西方占星平台的信息架构和未来入口，但当前只开发完整本命盘及其必须的平台闭环。实施、验收与停止条件以[本命盘优先开发计划](./natal-development-plan.md)、[对象库/新建分析/后台管理计划](./admin-object-analysis-plan.md)和[完整本命盘纵向切片契约](./natal-first-slice.yaml)为准。`NATAL-RELEASE`完成后停止，不自动进入行运、关系、预测或本文后续月份。本文 M0—M24 内容保留为长期能力目录，不代表当前授权或执行顺序。

> **当前生产发布约束：** 使用`fate.xiaoguiwk.top`和独立Docker Compose项目，建立独立Interstellar前端、FastAPI、账户存储、反向代理、日志与备份路径；不得通过Ledger项目出口或复用Ledger运行进程。游客无持久化，注册用户只读取本账户对象，每个人物只保留最后一次本命盘。当前首发使用服务端SQLite；未来并发和高可用需求出现时再迁移PostgreSQL，HTTP契约保持不变。

Interstellar V1是面向职业占星师、占星学习者和重度爱好者的西方占星专业计算平台。项目第一阶段不以AI解读、消费者内容或交易服务作为竞争点，而是先建立完整、可验证、可追溯的专业计算、图形和研究工作流。

项目采用“完整能力边界 + 分阶段成熟度”的策略：V1覆盖现代、古典与希腊化西方占星的主要计算体系，但每项能力根据验证程度标记为`Stable`、`Beta`或`Experimental`。未通过验证的能力可以存在，但不得包装为稳定能力。

V1同时交付：

- 专业Web工作台；
- 版本化REST API与TypeScript/Python SDK；
- 本地Docker Compose部署；
- 官方数据本地版本化；
- Canonical Astrology Schema；
- 算法卡、金标准、双实现差异测试和主代理自审制度；
- 全量计算、图形、数据导出和可重导入项目归档；
- 12个后端AnalysisModel、24个专题模型、35个分析目的、六类入口和统一AnalysisRecipe；
- 六类非AI报告、三种展示密度和可下钻证据链。
- 所有已计算结果的可达数据视图，以及无需生成完整报告的逐项上下文解读。

当前直接开发依据是[本命盘优先开发计划](./natal-development-plan.md)、[对象库/新建分析/后台管理计划](./admin-object-analysis-plan.md)、[竞品差距矩阵](./natal-competitor-gap.md)、[完整本命盘纵向切片契约](./natal-first-slice.yaml)和[V1技术开发说明书](./v1-development-spec.md)。入口、专题模型、全部计算与146项图形目录继续作为未来能力注册表保留；它们不再自动驱动本命盘完成后的开发。

## 2. 项目目标与成功标准

### 2.1 业务目标

1. 建立一个可以被专业用户长期使用和校验的西方占星计算底座。
2. 用统一Schema、版本和证据链降低不同技法、不同图表之间的数据割裂。
3. 通过开源和公共API获取早期专业用户反馈，沉淀验证案例和规则资产。
4. 为后续消费者产品、AI解释、新占术插件和商业服务提供稳定平台层。

### 2.2 V1成功标准

- 能力矩阵中所有`v1_required: true`项目已实现，并达到目标成熟度或公开降级原因；
- 关键天文位置、宫位、轴点和时间命中通过金标准与独立差异测试；
- 职业用户能完成示例体验、新增对象、选择分析内容、选择模型、计算、比较、分屏、证据检查、保存和导出；
- 12个内置AnalysisModel均能说明组件、规则、输入门槛、降级、输出图表、版本和成熟度；
- 24个TopicModel、35个AnalysisIntent和六类入口均能生成可检查、可复现的AnalysisRecipe与预检计划；
- 六类ReportProfile能够生成结构化ReportDocument；摘要、标准和完整技术版来自同一份报告；
- 同一输入在固定引擎、规则和数据版本下可以完全复现；
- Web、API、SDK、导出和项目归档使用同一Canonical Schema；
- 完成中英文界面与核心文档；
- Docker Compose在全新环境中可按文档部署、备份、升级和恢复；
- 完成数据许可、开源许可、隐私、安全、算法卡自审和双实现差异验证；外部专业评审为可选的增强证据，不是开发或发布的阻断条件；
- 未引入核心数据爬虫、付费数据库和商业内容逆向；
- 机器可读目录当前登记的99项专业计算均有Schema、算法卡、测试和可复现输出；
- 图形目录编号1—128逐项交付，编号129—146明确进入V1后消费者路线；
- 每次计算的`OutputManifest`能证明计算结果、能力、图形和降级之间的覆盖关系。
- 每个已物化结果集合都能在星盘配套视图、可访问表格或导出中查看；点击配置可得到版本化的基础/古典逐项解读，报告中心只负责综合。

### 2.3 不作为V1成败指标

- 大规模消费者注册数；
- 会员收入或咨询交易额；
- AI对话质量；
- 每日运势打开率；
- 企业级可用性和多区域容灾；
- 对现实事件的确定性预测准确率。

## 4. 执行策略

### 4.0 当前优先级覆盖：完整本命盘先行

当前开发不继续横向增加行运、返照、关系和更多技法，而只通过[本命盘优先开发计划](./natal-development-plan.md)和[完整本命盘纵向切片契约](./natal-first-slice.yaml)的`NATAL-0—NATAL-RELEASE`门禁。该决策保留全项目入口和长期能力目录，但暂停 M0—M24 的后续执行；本命盘发布后必须等待用户重新授权下一阶段。

截至2026-07-19，`NATAL-DATA`、`NATAL-TECHNICAL-EXPORT`和`NATAL-AI`契约门禁均已完成：V1必需的7类本地数据已可审计；Markdown、纯文本、复制和AI预览使用同一个确定性文档哈希；标准部署没有已配置第三方模型，预览不发送数据，提交受资料授权、精确载荷同意和配置状态共同约束。当前唯一活动门禁为`NATAL-RELEASE`；完成后停止。

本命盘首版必须形成完整产品闭环：

```text
示例盘或选择已保存人物
→ 从独立对象库“新增人物”只建档，不自动计算
→ 从全局“新建分析”选择本命技法，并选择已有对象或创建不入对象库的临时人物
→ 录入日期、时间精度、地点、时区候选、来源和可信度
→ 采用版本化推荐方案并确认5—7个关键参数
→ 预览实际生效参数、输出、降级和保存语义
→ 直接计算不可变本命Snapshot，而不是停留在对象建档
→ 首页直接显示本命轮盘与侧边设置
→ 查看星座、精确度数、宫位、运动/逆行状态及基础/结构/相位/古典/技术数据
→ 对单个指标点击解读
→ 复制或导出完整Markdown/纯文本技术推演
→ 在部署方已配置提供方且用户明确同意时，可选提交同一技术文档作AI解释
→ 保存人物、结果、Preset或其他导出
```

当前阶段只冻结“新增其他技法的真实计算”，不删除全局产品壳层、六类入口或未来盘型按钮。首页保留本命、行运、天象、推运、返照、关系等技法快捷入口，本命是当前唯一完整可运行项；未实现项必须显示所需输入、计划阶段和不可用原因，不得复用本命结果或打开相同占位弹窗。六类入口继续在分析中心和“新建分析”流程中出现，用于预填上下文。当前“完整”要求按信息维度不低于用户提供的竞品技术导出，并增加坐标、速度、状态、入出相、古典派生、数据版本、来源和可信度；这不授权复制竞品文字、专有权重或来源不明公式。

全局“新增人物”与“新建分析”是两个不同动作：独立对象库新增只创建可复用的`SubjectVersion`；新建分析先选择技法、专题或目的，再选择已有对象或内联创建临时对象，并依次完成推荐方案、关键参数和生效预检。内联对象默认只服务本次计算，用户可以显式保存为本人、亲友、伴侣、客户或其他关系人物。纯本命计算是一人一盘；单轮、双轮、三轮是渲染层概念，只有加入行运、推运、返照或第二人物等额外盘层时才使用多轮盘。

出生地点默认采用城市或乡镇级搜索，并自动解析经纬度与IANA时区候选；IANA时区使用可搜索候选选择器而非自由输入。经纬度默认由地点产生，只在高级设置允许人工覆盖并保存来源。街道或医院级地址不是本命盘的必填项，也不应为极小坐标差异增加不必要的隐私成本。国家代码不参与占星判断，只用于地名消歧、时区解析、区域显示和数据署名，应由地点结果派生并默认隐藏。

本命工作区使用分层参数：盘旁只保留规则方案、黄道、宫制、点位方案、相位方案、容许度方案和结果视图；高级设置再展开时间地点、黄道/Ayanamsa、宫制/高纬策略、行星/虚点/小行星/恒星/汉堡TNP、Lots、相位与逐项容许度、古典规则、坐标中心、渲染与导出。现代、古典、综合、自定义是版本化占星规则方案，不与外部AI模型混称。小限、法达、黄道释放等预测技法参数只在对应技法出现，不塞入本命设置。

本命结果至少提供本命轮盘、相位网格、点位表、宫位与宫主表、相位列表、结构与格局、基础解析、古典解析和技术数据/导出。轮盘与相位图只是同一Snapshot的不同视图，切换不重新计算；改变黄道、宫制、计算点位或相位集合才创建或复用新的Recipe与Snapshot。所有可解释指标在原位置提供“解读”；顶部不设置报告入口，综合结果与AI文本在当前结果和对象档案中就近查看。

对象库、统一新建分析和后台管理按[`admin-object-analysis-plan.md`](./admin-object-analysis-plan.md)的`OA0—OA6`门禁实施。首发后台只建立`user/admin/super_admin`角色、账户状态、会话撤销、用量/行为聚合、管理员审计、平台级AI/API提供方密钥管理和版本化平台预分析提示词。提示词支持全局默认与按模型覆盖，每次AI调用必须先应用代码内不可变安全边界，再应用平台提示词、用户重点和确定性分析文档；产物记录提示词版本/哈希，正文不暴露给普通用户。当前不存在的套餐、用户级额度和逐功能授权不进入界面；用量不是权限，配额待商业政策明确后单独建设。

“临时人物”是本次计算的内联输入，不自动进入人物库；登录用户可以在计算前或计算后显式保存为“本人”或某个关系角色，匿名用户默认仅保留短期结果。时间未知不得补`00:00`，因此宫位、四轴及其依赖解读必须阻断或按候选盘展示。太阳、月亮、轴点和计算型虚点不适用逆行判断时显示`不适用`，不得伪装成有意义的“顺行”。

完整技术推演是同一不可变Snapshot的确定性文档，不是报告，也不是AI生成内容。复制与Markdown/纯文本下载必须包含规范化输入、生效参数、点位落座/度数/宫位/速度/运动状态、宫头、相位、结构、古典状态、警告、来源和版本；只序列化已经计算的内容，不静默追加小行星、虚点、Lots或相位。

GPT、Kimi等名称只代表可以由部署方配置的提供方家族示例，不代表当前已经接通。未配置提供方、未通过可用性检查或用户未明确同意时，“提交至AI分析”必须禁用并显示原因；系统仍须允许用户复制或下载完全相同的技术文档。提交前必须预览提供方、精确模型、数据范围、目的、数据目的地、隐私/保留说明和是否保存响应。AI只能读取Snapshot或技术文档并生成独立标识的解释产物，不得计算星历、星座、宫位、相位或逆行，不得覆盖计算事实。

### 4.1 研发原则

- **纵向切片优先**：先打通入口—对象—模型/目的—Recipe预检—计算—快照—图形/报告—导出的全链路，再扩展技法数量。
- **编排显式**：用户可从技法、TopicModel或AnalysisIntent进入；最终必须落为版本化AnalysisRecipe，公开组件、Rule Pack、输入门槛、降级、成本和OutputManifest。
- **按需计算**：页面加载、切换报告密度和浏览图表目录不得全量计算；追加依赖必须重新预检。
- **报告有规则**：无AI报告只能由显式ReportRulePack和受控模板生成；算得出不等于可生成正式报告。
- **已算即有入口**：所有写入Snapshot的结果必须有视图、表格或导出消费者；显示密度可以收起或虚拟化，不能静默遗漏。
- **解读就近出现**：原子配置和单条事件在其轮盘、表格、网格或时间线上按需解读；报告只负责去重后的跨配置综合。
- **Schema先行**：公共结构先写Schema和契约测试，前后端从同一Schema生成类型。
- **算法卡先行**：复杂技法先确定流派、公式、参数和测试样本，禁止边写边猜。
- **验证早于Stable**：实现完成不等于Stable；Stable必须通过金标准、两个独立实现路径的差异测试和主代理算法卡自审清单。
- **按成熟度交付**：范围大不等于一次全部稳定，Beta/Experimental公开展示限制。
- **数据本地化**：运行时使用本地版本化数据，不让核心计算依赖公共在线API。
- **单一责任主体可维护**：V1采用模块化单体、单区域和Docker Compose控制运维复杂度；主代理对架构、领域决策和最终结果负唯一责任。
- **受控子代理并行**：子代理只接受边界清晰、输入输出已锁定、可独立验证的工作包；不得自行改变Schema、流派、公共ID、默认参数或发布成熟度。
- **目录驱动交付**：计算按`calculation_id`验收，图形按`view_id`验收，禁止只以“家族已支持”关闭工作项。

### 4.2 阶段门禁

每个阶段按以下顺序推进：

```text
范围和算法卡
→ Schema/API
→ 计算实现
→ 单元/属性测试
→ 金标准/差异测试
→ UI和导出
→ 文档和数据来源
→ 阶段评审
```

未通过阶段门禁的能力可以延后或降低成熟度，不得通过删除警告或放宽测试伪装完成。

### 4.3 关键路径、并行线与范围控制

24个月计划只有在以下关键路径不断裂时成立：

```text
Canonical Schema与时间/对象版本
→ Swiss Adapter与基础本命事实
→ Recipe/DAG/快照/Job
→ Alpha三模型与基础渲染
→ 事件搜索/推运/Rule Pack
→ 古典、时间主星、地理与专项能力
→ TopicModel证据规则与ReportRulePack
→ 128项专业图逐项闭环
→ 主代理统一审计、双实现验证、安全/许可/性能门禁
```

可并行但不得绕过关键路径的工作流：

- 前端分析中心可以在Schema冻结后用契约Mock开发，但上线前必须接真实Recipe Resolver；
- 主代理可将数据同步、渲染、报告模板、专业样本库及独立参考实现分配给不同子代理并行建设；
- 图表家族可以共享渲染器，但每个`view_id`仍需独立依赖、视觉和无障碍验收；
- 同一工作包不得由子代理自行声称完成；主代理必须重读差异、运行验证、核对目录覆盖并决定是否集成；
- 子代理可编写独立参考实现或验证夹具，但不得同时修改被验证的生产实现；
- 外部占星师、安全或许可专家的复核可随里程碑增加信心，但不替代主代理验收，也不阻断已满足强制门禁的开发。

范围控制规则：

- P0关键路径延误超过两周，立即冻结新增P1/P2能力并重排里程碑；
- 任何新增V1能力必须同时说明删除、延后或增加的资源，不接受“顺手加入”；
- M6、M12、M18均由主代理执行继续/降级/延长决策，以目录覆盖、自动测试、双实现差异验证、算法卡自审和已知限制为依据；
- `Experimental`可以进入V1目录，但不计入Stable完成率，也不能替代必需Stable能力；
- 计划以主代理单一责任主体为固定前提；计算、验证、渲染和文档工作包可由子代理并行，但不削减验证、许可、安全和可复现性门禁。

## 6. 执行资源计划

### 6.1 主代理与子代理工作流

| 执行单元 | 调度方式 | 职责 |
|---|---|---|
| 主代理 | 唯一持续责任主体 | 范围、架构、Schema、占星流派决策、任务分解、集成、回归、成熟度和发布签署 |
| 计算子代理 | 按单一技法或适配器临时调度 | 产出生产实现或独立参考实现；两者不由同一子代理同时修改 |
| 前端/渲染子代理 | 按不重叠的`view_id`家族调度 | 分析中心、SVG/Canvas/地图、报告阅读器和视觉回归夹具 |
| 数据/平台子代理 | 按Adapter、Manifest或运维边界调度 | 数据同步、PostGIS、任务、对象存储、备份和可观测性 |
| 验证子代理 | 与生产实现解耦调度 | 金标准、第二实现、差异、契约、E2E、视觉和性能测试 |
| 文档/许可子代理 | 按目录、来源或双语边界调度 | 算法卡来源、许可台账、术语、API和自托管文档草案 |
| 外部专家 | 可选、非阻断 | 对占星、安全、许可或双语结果提供附加评议；不承担唯一签署权 |

调度约束：主代理任意时刻只保留一个工作包为集成主线；子代理可并行处理互不覆盖的文件或可独立应用的补丁。每个子代理工作包必须给定稳定ID、可写边界、输入、输出、验证命令和禁止决策项。主代理合并前必须独立重跑验证，不接受子代理的自我完成声明作为证据。

### 6.2 成本策略

V1默认不采购数据许可，主要成本为：

- 单区域服务器、数据库、对象存储和流量；
- 域名、邮件、备份和监控；
- 独立参考实现、差异验证和可选外部专业评议；
- 安全和许可证专项审查；
- 必要的地图瓦片或地理编码服务；
- 开发与AI工具。

成本控制措施：

- AGPL使用Swiss Ephemeris；
- 官方数据本地化，不按请求调用收费天文API；
- 常用恒星和小行星内置，长尾对象按需缓存；
- Natural Earth承担全球底图；详细地图采用可替换供应商；
- 公共服务限流、排队和按优先级降级；
- V1不承诺SLA，不为高峰提前建设分布式架构。

### 6.3 什么时候必须付费

以下情况发生时启动采购评估：

| 触发条件 | 可能采购 |
|---|---|
| 产品闭源或提供不兼容AGPL的商业服务 | Swiss Ephemeris Professional License |
| 公共地图流量超过自建能力或免费政策 | 商业瓦片/地理编码服务 |
| 需要企业级监控、备份或多区域 | 云基础设施和可观测性服务 |
| 需要商业使用的高质量名人出生时间库 | 书面数据授权；若无授权则不做 |
| 需要商业报告文本和专业规则 | 原作者授权或主代理依公开来源独立建设内容库 |
| 需要增强Stable的第三方信任 | 可选付费占星师、安全或许可专家评议；未采购不阻断强制门禁 |

## 7. 数据策略与覆盖判断

### 7.1 免费来源能否覆盖V1

结论：在项目整体采用AGPL、算法自行实现、核心数据本地化的前提下，免费官方数据能够覆盖V1的确定性计算和制图需求。

截至2026-07-19，V1必需免费来源已全部本地化并锁定：Swiss Ephemeris、IANA tzdb、GeoNames、Timezone Boundary Builder、JPL DE442、IERS finals2000A和Natural Earth共7项。平台通过`/api/v1/datasets`公开实际版本、校验和、许可证、用途和适配状态；运行时零爬虫、零公共API硬依赖。JPL、IERS和Natural Earth当前是“数据就绪、消费适配待开发”，因此不虚假计入已发布计算/制图能力。Gaia、MPC、OSM、NASA Eclipse和Wikidata保留为非阻断的未来增强来源。

免费数据能够覆盖：

- 太阳、月亮、行星、节点、宫位、轴点、速度、逆行；
- 地心、日心和拓扑中心坐标；
- 小行星轨道、固定星天文位置；
- 现代时区、DST、全球地点和时区边界；
- 地球定向、闰秒、日月食校验；
- 世界底图和可授权的详细地图数据；
- 由上述事实派生的相位、格局、中点、谐波、返照、推运、合盘、地理线和绝大多数图形。

免费数据不能自动提供：

- 完整且可靠的1970年前地方时间事实；
- 大量人物经验证的精确出生时间；
- 商业可用的中文解释文本；
- 公认的主题评分权重和事件概率；
- 出生时间校正的标准答案；
- 企业级托管、地图瓦片和查询SLA；
- 商业软件专有算法和内容。

### 7.2 数据获取边界

| 分类 | 做法 |
|---|---|
| 官方发布包/Dump | 允许，保存版本、校验和、许可和署名 |
| 官方API/TAP | 允许，遵守限流，按需缓存并记录查询来源 |
| 手工授权导入 | 允许，保存授权范围和来源 |
| 公共网页抓取 | 不作为核心数据来源 |
| Astro-Databank爬虫 | 禁止 |
| 公共Nominatim批量/自动完成 | 禁止 |
| 商业App报告和规则抓取 | 禁止 |
| Google地图数据提取 | 禁止 |

具体来源、URL和同步频率见技术说明书第10节。

## 8. 质量、发布与变更管理

### 8.1 发布通道

| 通道 | 对象 | 承诺 |
|---|---|---|
| `nightly` | 开发和自动测试 | 不保证数据迁移和API稳定 |
| `alpha` | 早期专业测试者 | 核心工作流可用，允许破坏性变更 |
| `beta` | 更广专业用户 | 迁移可控，变更有公告，能力限制公开 |
| `v1` | 正式开源和自托管 | `/api/v1`兼容、迁移文档、已知限制和安全修复 |

### 8.2 变更规则

- 需求变更先更新本计划和能力矩阵，再进入研发任务；
- 新增技法必须有算法卡、负责人、阶段和成熟度目标；
- 新增或修改AnalysisModel必须更新模型卡、语义版本、组件DAG、兼容性矩阵和OutputManifest；
- 新增或修改TopicModel、AnalysisIntent、ReportRulePack或ReportProfile必须更新`analysis-catalog.yaml`、Recipe回归、模板清单和迁移说明；
- 删除或延后`v1_required`能力必须记录理由和影响；
- 数据版本升级必须跑完整金标准和差异测试；
- 公共字段重命名或语义变化必须发布新Schema版本；
- V1发布后，`/api/v1`只允许向后兼容新增和错误修复。

### 8.3 阶段评审材料

每次阶段评审提供：

- 能力矩阵变化；
- AnalysisModel目录、版本和降级行为变化；
- TopicModel、AnalysisIntent、入口、Recipe和报告规则覆盖变化；
- 已通过和失败的金标准；
- 差异测试报告；
- 性能、错误和队列指标；
- 数据和许可证变化；
- 已知问题、技术债和安全问题；
- 用户反馈与下一阶段调整；
- Stable/Beta/Experimental变更建议。

## 9. 风险登记

| 风险 | 概率 | 影响 | 预警信号 | 缓解与应对 |
|---|---|---|---|---|
| 主代理集成主线被过多并行工作打断 | 中 | 高 | 同时存在多个重叠补丁或连续两个里程碑延期 | 一个集成主线、子代理不重叠可写边界、每批小步验证后再分派下一批 |
| 高级技法流派冲突 | 高 | 高 | 同名能力结果不一致 | 算法卡明确流派和参数，允许并列变体，不静默合并 |
| 历史时区错误 | 高 | 高 | 同地点同时间存在权威冲突 | 候选结果、可信度、人工修正、数据版本和警告 |
| Swiss许可误用 | 中 | 高 | 出现闭源或非AGPL发行需求 | V1保持AGPL；商业化前采购专业许可和法律审查 |
| 双实现不独立或自审流于形式 | 中 | 高 | 两实现共享同一错误路径或算法卡清单无证据 | 生产与参考实现分开上下文/子代理，主代理逐项链接测试、差异报告和来源 |
| 数据源政策变化 | 中 | 中 | API限流或许可调整 | 本地版本化、可替换Adapter、许可证台账和同步告警 |
| 图形性能不足 | 中 | 中 | 大型盘SVG过大、交互卡顿 | SVG/Canvas/WebGL分层、符号聚合、异步导出 |
| 任务队列拖垮公共服务 | 中 | 高 | 排队时间和超时持续上升 | 限流、配额、优先级、取消、任务预算和降级 |
| 用户敏感资料泄露 | 低到中 | 极高 | 日志含出生资料或越权测试失败 | RLS、应用层加密、日志脱敏、安全门禁、短期分享 |
| API与Schema漂移 | 中 | 高 | TS/Python结果不一致 | 单一Schema源、代码生成、契约测试和版本策略 |
| 主题评分被误解为预测 | 高 | 中 | 用户传播“成功概率” | 分拆活跃/支持/压力/确定度，展示证据和非确定性说明 |
| 分析模型变成不透明黑箱 | 中 | 高 | UI只显示模型名称，快照无法解释组件 | 模型卡、组件DAG、版本哈希、输出Manifest和兼容性测试作为发布门禁 |
| 入口、模型、计算和图表失去可达性 | 中 | 高 | 目录项目无任何Recipe引用 | CI可达性检查；无入口/依赖/Recipe的能力移至未来或实验目录 |
| 报告规则和模板规模失控 | 高 | 高 | 计算已完成但大量TopicModel无法成文 | Finding优先、受控模板、分阶段report_ready；主代理按主题批次调度规则/样本子代理并统一验收 |
| 未授权商业内容进入规则库 | 中 | 极高 | 模板或规则与商业报告高度相似且无来源 | 来源台账、代码审查、许可门禁；专有模型默认不可执行 |
| 免费地图服务不可用 | 高 | 中 | 限流或瓦片失败 | Natural Earth本地底图、供应商Adapter、自建或采购 |

## 10. V1后拓展路线

### 10.1 消费端产品

前置条件：V1核心计算稳定、主题证据链可解释、具备至少一个完整用户研究周期。

后续能力：

- 简化出生资料输入和引导；
- 个人、关系、职业、年度专题报告；
- 每日、每月、每年主题时间线；
- 事件、情绪、关系和项目记录；
- 每周/每月复盘和历史周期对照；
- 关系邀请、双方权限和共同档案；
- 订阅和单次报告。
- 实现图形目录编号129—146，包括主题热力图、领域活动曲线、项目/沟通/签约窗口、事件反馈与个人敏感配置；这些图不得提前计入专业V1完成率。

### 10.2 AI能力

前置条件：Canonical Snapshot、Evidence和Rule Pack稳定。

本命首切片中的“可选AI提交连接器”不代表本节能力已经实现。它只负责列出部署方实际配置的提供方、让用户预览并同意发送同一份确定性技术文档、保存独立响应或回退到手动复制；标准部署不配置任何模型。下列自然语言控制、长期记忆、综合报告和跨证据推理仍属于V1后能力。

后续能力：

- 根据结构化证据链解释计算结果；
- 自然语言筛选和控制图表；
- 结合用户授权记录进行长期复盘；
- 报告生成、问题澄清和多语言表达；
- 对相互矛盾的证据进行显式综合。

约束：AI不得直接计算行星位置、星座、宫位、逆行和精确相位；不得把推断写回计算事实；不得输出确定性灾难、医疗、法律或投资结论。任何提供方接入必须由部署方配置并通过许可、安全和隐私审查，不能仅因目录中出现GPT、Kimi等名称就宣称已经接通。

### 10.3 新占术插件

平台层预留统一Envelope：插件ID、版本、输入、TimeSpec、Location、来源、成熟度、Evidence、Job和Export。每个系统使用独立领域Schema。

候选顺序由后续市场和专业资源决定：

- 印度占星；
- 八字；
- 紫微斗数；
- 奇门遁甲；
- 其他历法和占术系统。

V1不为这些系统伪造通用“星盘字段”，只提供公共平台协议。

### 10.4 专业商业能力

- 占星师客户管理、咨询前问卷和报告交付；
- 预约、支付、退款和争议处理；
- 团队Workspace、角色、审计和机构模板；
- 商业API、计量、API Key管理和SLA；
- 课程、案例库和专业认证工具。

### 10.5 基础设施升级

- Kubernetes或托管容器；
- 多区域读取、备份和灾难恢复；
- 分布式任务和分析型数据库；
- 全量或分层星表、小行星和地图镜像；
- 企业级密钥管理、审计和合规；
- 商业地图、地理编码和数据授权。
