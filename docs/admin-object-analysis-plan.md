# Interstellar 对象库、统一新建分析与后台管理实施计划

| 字段 | 值 |
|---|---|
| 文档版本 | 1.1.0 |
| 生效日期 | 2026-07-19 |
| 当前状态 | OA0—OA5 已进入实现与验收；OA6 待生产发布 |
| 适用范围 | 专业本命盘首发与其后可复用的平台能力 |

## 1. 已确认的信息架构

顶部导航固定为：

```text
工作台 / 分析中心 / 技法排盘 / 对象库 / 新建分析 / 账户
```

- 删除顶部“报告”入口。AI分析文本和技术导出在对应计算结果中就近查看，不建立与结果脱节的空报告中心。
- 删除顶部“计算方法”入口；“技法排盘”保留，承载本命、行运、次限、返照、关系等专业技法目录。
- “新建分析”是全站唯一的全局主动作。
- “对象库”使用独立路由`/objects`；用户中心只显示最近对象、本人档案摘要和进入对象库的快捷入口，不把两个页面合并。
- 后台管理使用独立路由`/admin`，不在普通用户顶部导航中展示。前端隐藏不是授权，所有后台接口必须由服务端鉴权。

## 2. 独立对象库

### 2.1 页面职责

对象库保存可被多次计算引用的业务对象，不是通讯录，也不自动触发计算。页面只提供：

- 对象类型标签、搜索、筛选、排序和最近使用；
- 对象卡片的出生资料、关系标签和是否已有结果的简要状态；
- 新增、编辑、设为默认、取消默认、删除与示例显隐；
- 对象库不得提供“打开最新本命”“开始本命分析”或“重新分析”按钮；
- 用户需要计算时，必须回到工作台，通过全局“新建分析”选择已有对象；
- 同一人物重复本命计算只保留最新结果，旧结果不进入普通用户历史。

### 2.2 对象类型

| 对象类型 | 稳定类型 | 最小资料 | 首发状态 |
|---|---|---|---|
| 人物 | `person` | 名称、日期、时间精度、地点/时区 | 本命首发可用 |
| 关系 | `relationship` | 两个或更多人物及关系类型 | 后续关系技法启用 |
| 事件 | `event` | 事件名称、时间、地点、来源 | 对象建档可先实现；事件技法后续启用 |
| 项目 | `project` | 名称、关键启动时刻、地点、负责人 | 对象建档可先实现；项目分析后续启用 |
| 组织 | `organization` | 名称、成立/生效时刻、地点 | 对象建档可先实现；世运分析后续启用 |
| 地点 | `location` | 名称、经纬度、IANA时区 | 地理技法后续启用 |
| 问题/案例 | `question_case` | 问题、提问时刻、地点、资料授权 | 卜卦/研究功能后续启用 |

未实现的对象类型不得打开与人物相同的假表单。可以显示用途和计划阶段，但创建按钮必须真实禁用并说明原因。对象类型启用时必须同时完成Schema、API、隔离、删除、导入导出和至少一个真实消费入口。

### 2.3 对象库与用户中心边界

| 对象库 | 用户中心 |
|---|---|
| 人物、关系、事件、项目、组织、地点、问题/案例 | 账户资料、登录安全、隐私、主题、默认设置 |
| 资料版本、来源、关系、资料维护 | 本人档案快捷入口、最近对象、默认人物 |
| 不发起分析、不打开结果 | 会话管理、数据导出、删除账户 |

“本人”仍是`person`对象，只是一个账户最多有一个活动的主要本人档案；它不被复制成第二套用户资料模型。

### 2.4 示例人物与工作台默认选择

- “阿特拉斯”作为可删除的虚拟示例人物进入对象库，并明确标记为非真实资料。注册用户的示例显隐偏好写入账户，游客偏好只写入当前浏览器。
- 登录用户新增或修改人物时可以设为默认人物；对象库提供设为默认、取消默认、修改和删除操作。
- 工作台打开时按固定顺序解析对象：`用户显式默认人物 → 未删除的阿特拉斯 → 最近新增人物 → 新建分析空状态`。
- 如果选中的人物尚无本命结果，只显示该人物和“新建分析”按钮，不得复用阿特拉斯或其他人物的轮盘。
- 删除默认人物时，后端在同一事务中清空`default_person_id`；下一次加载自动按上述顺序降级。
- “最近新增人物”按`created_at`排序，不因重新计算、AI分析或资料编辑改变。

## 3. 统一“新建分析”

### 3.1 五步流程

```text
1 选择要分析的内容
→ 2 选择已有对象或录入临时对象
→ 3 选择推荐方案并确认关键参数
→ 4 预览实际生效参数、输出与降级
→ 5 计算并进入结果工作台
```

本命首发中，第1步默认进入“技法排盘 → 本命盘”，同时保留专题和分析目的的未来入口；未实现入口明确标记“规划中”。临时对象默认不保存，登录用户可显式勾选保存到对象库，游客不能持久化。

### 3.2 推荐方案

新建分析不把全部专业参数一次平铺，也不让用户在完全不了解时自行拼装。系统先选中版本化推荐方案，再让用户确认5—7个高影响参数：

1. 分析体系：现代、古典、希腊化或专业综合；
2. 黄道：回归黄道或恒星黄道/Ayanamsa；
3. 宫位制；
4. 点位集合；
5. 相位集合；
6. 容许度方案；
7. 未知时间/高纬处理（仅条件触发时出现）。

每个方案必须展示：

- 用户可见名称和适用场景；
- “平台推荐/常用配置/特定流派”标签；
- `preset_id`、版本和变更日期；
- 默认依据：公开文献、上游计算库支持、产品验证样本或流派规则；
- 与上一个方案相比会新增、删除或改变什么；
- 哪些参数用户可覆盖，哪些是语义必需项；
- 不适用、Beta和高纬/未知时间降级。

禁止使用“行业唯一权威”“最准确”等无法证明的表述。默认方案是可操作基线，不代表占星行业只有一种标准。

### 3.3 生效参数预检

运行前显示“你将得到什么”，而不是只显示内部Recipe ID：

- 对象与时间/地点可信度；
- 推荐方案及用户覆盖项；
- 实际生效的黄道、Ayanamsa、宫位制、点集、相位集和容许度；
- 必需且锁定、推荐默认、用户选择、不可用和降级项；
- 将生成的轮盘、矩阵、表格、解析和导出；
- 是否同步完成、预计耗时、是否需要额外输入；
- 结果会临时保存还是覆盖对象最新结果。

确认后形成不可变Recipe内容哈希。返回修改必须生成新Recipe；渲染颜色、显隐和面板布局只更新RenderSpec，不重新计算。

## 4. 后台管理

### 4.1 角色与入口

首发只建立最小角色：

| 角色 | 能力 |
|---|---|
| `user` | 管理自己的对象、计算、导出和AI结果 |
| `admin` | 查看运营摘要和用户状态；执行受审计的用户运营操作；管理非根级配置 |
| `super_admin` | 增删管理员、管理服务密钥和系统级配置；不可删除最后一个超级管理员 |

当前实现只有“游客/登录用户＋数据所有者隔离”，没有角色、套餐、逐功能授权或额度模型。本计划实施前，后台路由不得对外开放。第一位`super_admin`通过服务器环境变量或一次性迁移命令建立，不能依赖一个公开注册接口。

### 4.2 后台页面

```text
/admin/overview        运营概览
/admin/users           用户列表与状态
/admin/users/:id       用户详情、用量、行为和操作
/admin/admins          管理员管理（super_admin）
/admin/providers       AI/API提供方与密钥（super_admin）
/admin/audit-log       管理操作审计
```

普通用户导航不展示后台。无管理员角色访问任何`/admin`页面或`/api/v1/admin/*`接口时，服务端返回`403`；未登录返回`401`。

### 4.3 用户列表与状态

用户列表展示：邮箱、显示名称、角色、状态、注册时间、最近登录、活动会话数、对象数、成功/失败计算数、AI请求/令牌数、最近活动时间。支持搜索和状态筛选。

账户状态采用明确状态机：

| 状态 | 含义 | 登录与数据 |
|---|---|---|
| `active` | 正常 | 可登录，数据可用 |
| `suspended` | 临时停用，可设置截止时间和原因 | 禁止新登录，撤销活动会话，数据保留 |
| `disabled` | 人工禁用，无自动恢复时间 | 禁止登录，撤销活动会话，数据保留 |
| `deletion_pending` | 删除宽限期 | 禁止登录，等待物理删除或管理员取消 |
| `deleted` | 已物理清理 | 只保留不可逆去标识运营聚合和审计引用 |

“停用”和“禁用”不能只是前端标签；鉴权中间件必须拒绝并撤销会话。删除默认采用软删除和宽限期，再执行物理清理。管理员新增用户应发送一次性设置密码/邀请流程，不让管理员知道用户永久密码。

所有停用、恢复、禁用、删除、新增用户、修改角色、管理员变更和密钥变更都必须要求原因、二次确认并写入不可修改的审计日志。危险操作返回操作ID，并支持按操作者、目标、时间和结果检索。

### 4.4 流量、用量与行为

“流量”分成三种指标，禁止混为一个数字：

- HTTP：请求数、错误率、响应时间、估算上下行字节；
- 业务用量：分析启动/成功/失败、对象创建、导出、AI提交；
- AI用量：提供方、模型、请求数、输入/输出令牌、失败和成本估算。

首批行为事件只记录：注册、登录成功/失败、登出、对象创建/更新/删除、分析开始/完成/失败、导出、AI预览/提交/失败和后台操作。事件只保存稳定事件名、不可逆用户ID、时间、结果、耗时、入口ID、技法/预设ID和错误码。

禁止把姓名、邮箱明文副本、出生资料、经纬度、问题原文、星盘结果、报告/AI正文、密码或API Key写入行为事件。首发不做键盘记录、鼠标轨迹、会话回放或第三方广告画像。游客只进入短期、去标识聚合。

运营首页至少显示：当日/7日/30日注册与活跃用户、成功分析数、错误率、AI调用、主要入口、主要失败码和服务健康；没有可靠数据的卡片显示“尚未采集”，不得生成演示数字。

### 4.5 API Key/提供方管理

首发管理的是平台级第三方提供方密钥，不是给用户发放Interstellar开发者API Key。页面支持：

- DeepSeek等提供方名称、Base URL、允许模型和默认模型；
- 新增/替换密钥、启用/停用、连接测试和轮换；
- 只显示掩码和末4位，保存后永不回显完整值；
- 最近测试时间、测试结果、最近使用和配置版本；
- 可选全局请求/令牌保护阈值，防止失控消费。

后台同时提供版本化“平台预分析提示词”：

- 一个全局默认提示词，并允许按`provider_id + model_id`设置覆盖；
- 每次AI调用的固定装配顺序为“代码内不可变安全边界 → 当前已发布平台预分析提示词 → 用户选择的分析重点/格式 → 同一份确定性分析文档”；
- 管理员提示词不能替换、弱化或绕过代码内安全边界，也不能要求模型重算或覆盖星历事实；
- 提示词采用`draft → active → retired`版本，发布、回滚和按模型覆盖均写入管理员审计；
- 每个AI产物保存提示词版本、内容哈希、提供方和精确模型，保证响应可追溯，但普通用户和公共接口不返回提示词正文；
- 后台支持长度/变量校验、最终装配预览和测试调用，预览必须对人物私密字段和密钥脱敏；
- 提示词正文属于受限运营配置，不进入前端Bundle、行为事件、错误响应、普通用户导出或客户端日志。

密钥必须由服务端使用部署主密钥加密后落库，或继续使用容器Secret/服务器环境变量。禁止写入前端Bundle、`NEXT_PUBLIC_*`、Git、日志、行为事件、错误响应和导出。聊天中暴露过的密钥在生产发布前必须轮换。

### 4.6 当前不做细粒度权限

本轮不建设“给单个用户勾选宫位、相位、导出、AI等功能”的权限矩阵，也不把尚未存在的套餐能力做成空设置。

用量、限流和权限是三个不同概念：

- 角色权限回答“可以执行哪类管理动作”；
- 用量回答“实际使用了多少”；
- 配额/套餐回答“一个周期最多允许多少”。

当前只实施`user/admin/super_admin`角色和所有者隔离。月度计算数、AI令牌、对象数量、存储、API速率、导出能力和Beta功能开关等配额，等计费/套餐政策确定后再建设`Entitlement + Quota`模型，后台在此之前不显示“用户权限”标签。

## 5. 数据与接口实施清单

### 5.1 SQLite首发增量

- `accounts`增加：稳定`account_id`、`role`、`status`、`last_login_at`、`suspended_until`、`disabled_at`、`deletion_requested_at`和状态原因；
- `sessions`增加统一撤销能力；账户失效时事务内撤销全部会话；
- 新增`objects`、对象类型明细与不可变版本表；人物表迁移时保持旧ID映射；
- 新增`usage_events`和`usage_daily_rollups`；
- 新增`admin_audit_logs`；
- 新增`provider_configs`和`provider_secrets`；
- 新增`ai_prompt_profiles`，保存全局/按模型作用域、状态、版本、哈希、正文密文或受限字段、创建/发布者和时间；
- 所有迁移必须可重放、可备份恢复，并有旧账户数据迁移测试。

### 5.2 最小后台接口

```text
GET    /api/v1/admin/overview
GET    /api/v1/admin/users
POST   /api/v1/admin/users
GET    /api/v1/admin/users/{account_id}
POST   /api/v1/admin/users/{account_id}/suspend
POST   /api/v1/admin/users/{account_id}/disable
POST   /api/v1/admin/users/{account_id}/reactivate
POST   /api/v1/admin/users/{account_id}/delete
GET    /api/v1/admin/admins
POST   /api/v1/admin/admins
DELETE /api/v1/admin/admins/{account_id}
GET    /api/v1/admin/providers
PUT    /api/v1/admin/providers/{provider_id}
POST   /api/v1/admin/providers/{provider_id}/test
GET    /api/v1/admin/ai-prompts
POST   /api/v1/admin/ai-prompts
POST   /api/v1/admin/ai-prompts/{prompt_id}/publish
POST   /api/v1/admin/ai-prompts/{prompt_id}/retire
POST   /api/v1/admin/ai-prompts/preview
GET    /api/v1/admin/audit-log
```

变更接口要求CSRF防护/同源校验、`If-Match`或版本号避免覆盖、幂等键、二次确认字段和审计。列表分页，后台不得返回密码哈希、会话令牌、完整API Key、完整出生资料或AI正文。

## 6. 实施顺序与验收

| 阶段 | 交付 | 阶段出口 |
|---|---|---|
| OA0 导航与契约 | 删除报告/计算方法顶部入口；固化路由、Schema和状态机 | 每个入口职责唯一 |
| OA1 对象库 | `/objects`、人物新增/修改/删除/默认、示例显隐 | 登录账户只见自己的对象；页面不存在分析与结果打开按钮 |
| OA2 新建分析 | 五步构建器、推荐方案、关键参数、生效预检 | 同一选择生成可复现Recipe；无假按钮 |
| OA3 后台鉴权 | 角色、状态、超级管理员引导、`/admin`门禁 | 越权测试、最后超级管理员保护通过 |
| OA4 用户管理 | 列表、详情、新增、停用/禁用/恢复/删除、审计 | 状态真实影响登录和会话，危险操作可追溯 |
| OA5 观测与AI配置 | 用量/行为聚合、运营概览、提供方密钥、全局/按模型预分析提示词 | 无敏感事件载荷，密钥不回显，提示词版本/哈希/装配顺序可追溯 |
| OA6 发布 | Docker、备份、迁移、回滚、`fate.xiaoguiwk.top` | 生产健康、TLS、账户隔离和管理员E2E通过 |

最低验收场景：

1. 游客可以临时新增人物并计算，但刷新或会话结束后不会出现在对象库；
2. 用户A与用户B无法互见对象、结果、AI文本或后台数据；
3. 登录用户可在对象库新增和维护人物，但只能从工作台新建分析；重算覆盖旧结果；
4. 新建分析清楚说明推荐方案来源、关键参数和最终生效参数；
5. 被停用/禁用用户的所有会话失效且不能重新登录；
6. 普通用户不能访问任何后台页面和接口；
7. 最后一个`super_admin`不能被删除或降级；
8. 管理员看不到密码、会话令牌、完整API Key、出生资料和报告正文；
9. 密钥轮换后旧密钥不可继续调用，操作进入审计；
10. 全局与按模型提示词按固定优先级装配，AI产物记录生效版本/哈希，普通用户无法读取提示词正文；
11. Docker发布后主页、API健康、注册登录、对象库、新建分析和后台管理通过同源HTTPS访问。
12. 默认人物、示例显隐和最近新增回退在刷新、登录、退出、删除人物后保持一致，且不会把一个人物的结果显示在另一个人物名下。

## 7. 明确非目标

- 本轮不实现套餐、支付、订阅、用户级细粒度功能授权和开发者API Key发放；
- 不把后台行为统计扩展为监视用户私人输入或内容；
