# iOS 四盘解析卡片实现矩阵

> 本文件用于防止漏卡、漏视觉元素或漏文字层。卡片顺序、核心视觉和必显内容以 Obsidian `5-语料设计.md`、`6-解读设计.md` 为准；困难交互属于二阶段，不影响一阶段静态内容完整性。

## 通用必填

每张卡片必须同时具备：

- 固定 `cardID`、标题、图标；
- Obsidian 指定的核心视觉；
- 真实计算事实；
- 一句始终可见的摘要；
- 可展开的约 100 字详情；
- 无数据时的完整空状态；
- 中英文单语显示；
- 私有内容键，不把正式原创语料写入公开 Swift。

内容键统一为 `<盘型前缀>.<cardID>.sample`：

- 本命：`natal.<cardID>.sample`
- 天象：`current-sky.<cardID>.sample`
- 行运：`transit.<cardID>.sample`
- 次限：`secondary.<cardID>.sample`

公开代码只保留卡片结构、事实字段和渲染能力，不保留解释正文降级。正式摘要、约 100 字详情及选择规则由按盘拆分、被 Git 忽略的私有 source pack 构建为 `PrivateCorpus-<locale>.json`；Release 只接受 `approved`。

## 一阶段暂缓交互

- 卡片与轮盘联动；
- 点击行星或相位进入局部聚焦；
- 7/30/90 天切换；
- 点击时间轴跳转事件时刻；
- 点击日历展开单日详情；
- 雷达轴点击；
- 叠加本命盘/进入行运盘按钮。

摘要/详情展开不属于暂缓项，必须保留。

## Ask 问事结果模块

Ask 不计入四盘 28 张固定卡，也不复用四盘的 `cardID`。三种模式必须保留以下结果模块：

| 模式 | 必显结果 | 消费者卡片 | 专业层 |
|---|---|---|---|
| 会发生吗 | 答案、可能性、五档结论 | 当前连接、推动因素、阻碍因素、月亮进展 | 代表星、力量、接纳、关键相位、月亮下一相位/空亡、评分明细 |
| 选哪个 | 每项实际名称、总计 100% 的概率、完整排名、接近提示 | 领先项、差距、主要支持与阻碍 | 每项宫主星、力量、连接、评分明细 |
| 什么时候做最好 | 第一推荐、两个备选、独立适合度、周/月峰值日 | 最佳窗口、支持、风险、月亮状态 | 每个候选的目标宫主星、力量、连接与评分明细 |

Ask 卡片摘要与详情仍来自私有内容包，但评分、概率、排名和专业事实直接来自计算。不得为了增加文案量给每种盘面写固定答案。轮盘覆盖层必须包含相关宫位、代表星标签和关键相位，且不永久改变其他四盘的轮盘。

## 自动验收

`scripts/check-ios-card-contract.sh` 与 Debug 运行时断言共同检查：

- 四盘共 28 个固定 ID 及顺序；
- 每张卡标题、摘要、详情和最低事实数量；
- 天象 8 领域、12 个生活领域、完整星体表、本周 7 天日历；
- 旧本命卡 ID 不得回流；
- 已明确否决的内部话术不得进入消费者 Swift。
- Ask 三种入口、概率/适合度、选择题不同领域、最多五项、范围上限、进度取消和专业分析结构；
- 字体设置四档、Report 三分类、主要入口 44pt，以及 9pt 以下文字只存在于轮盘内部。

真机视觉、长英文、中文、Dynamic Type、VoiceOver 与正式私有语料逐卡审核仍需人工完成，不能由构建成功替代。
