# 组件职责边界

> 每类组件有明确的职责范围，禁止越权。

---

## 组件分类与职责

### workspaces/ — 主工作区

**职责**：
- 页面布局（四区结构：参数 + 轮盘 + 右侧面板 + 底部面板）
- 状态编排（useState、useEffect、useMemo 等）
- 调用 `insight/` 中的 `build*` 函数获取解读数据
- 调用 `hooks/` 中的异步流程
- 将数据通过 props 传递给子组件

**禁止**：
- 直接构建解读数据（不写 `build*` 逻辑，全部调 `insight/` 函数）
- 内联异步请求逻辑（计算、AI 分析等应封装为 hooks）
- 包含轮盘渲染逻辑

### panels/ — 面板组件

**职责**：
- 接收数据 props，渲染解读面板、计算结果面板
- 包含面板内部交互逻辑（Tab 切换、展开/折叠）
- 纯展示 + 内部交互，不发起 API 请求

**禁止**：
- 直接调用 `interstellar-api.ts` 中的函数
- 包含业务逻辑判断（如"哪些相位算支持性"应在 `insight/` 中完成）

### wheels/ — 轮盘组件

**职责**：
- 接收 snapshot + renderSpec + controls，渲染 SVG 轮盘
- 处理轮盘交互（缩放、选中行星/宫位）
- 纯渲染组件

**禁止**：
- 请求计算数据
- 包含解读逻辑
- 硬编码星座/宫位标签（从 `insight/shared.ts` 或 `components/lib/` 读取）

### forms/ — 表单组件

**职责**：
- 受控组件，通过 props 接收 value 和 onChange
- 表单验证逻辑
- 回调上传（不直接触发计算）

**禁止**：
- 直接调用计算 API
- 包含业务逻辑

### results/ — 结果展示组件

**职责**：
- 接收计算结果数据，按列/行渲染表格和结果卡片
- 纯展示

**禁止**：
- 数据转换逻辑（应在 `insight/` 或 `lib/` 中完成）

### lib/ — 共享组件工具

**职责**：
- 跨组件复用的类型定义（`chart-types.ts`）
- 常量（`chart-constants.ts`、`chart-labels.ts`）
- 工具函数（`chart-utils.tsx`）
- 本地解读构建器（`local-interpretation-builder.ts`）

**禁止**：
- 包含盘型专有逻辑（应放 `insight/` 对应文件）
- 发起 API 请求

## 数据流向

```text
用户操作（点击计算/AI按钮）
    → workspace 组件捕获事件
    → 调用 hook（useChartCalculation / useAiAnalysis）
    → hook 调用 interstellar-api.ts
    → API 返回数据
    → workspace 用 useMemo 调用 insight/build* 函数
    → 生成解读数据
    → 通过 props 传递给 panels/wheels/results
```

**核心原则**：数据向下流，事件向上冒。workspace 是唯一的数据汇聚点。

## 状态归属规则

| 状态类型 | 归属 | 说明 |
|---|---|---|
| 表单输入值（日期、设置选项） | workspace 的 useState | 通过 props 传给 forms |
| 计算结果 | workspace 的 useState | 通过 props 传给 panels/wheels/results |
| 解读数据（insight 输出） | workspace 的 useMemo | 通过 props 传给 panels |
| 面板内部 Tab 选中状态 | panels 内部 useState | 不需要上传 |
| 轮盘缩放/选中状态 | wheels 内部 useState | 不需要上传 |
| AI 分析加载/结果状态 | workspace 的 useState | 通过 props 或 hook 管理 |

## 检查清单

- [ ] workspace 中是否有内联的 `build*` 逻辑（应调 `insight/` 函数）
- [ ] workspace 中是否有内联的 API 请求（应封装为 hook）
- [ ] panels 中是否有 API 调用（应通过 props 接收数据）
- [ ] wheels 中是否有解读逻辑（应只接收渲染数据）
- [ ] 新增组件是否放在正确的目录
- [ ] 数据流是否符合"向下流、向上冒"原则
