# 语料库引用约束

> 开发解读功能时，所有面向用户的文本必须从语料库（`5-语料设计.md`）中引用，禁止临时硬编码。

---

## 语料库位置

每个盘型的语料库文件：

```text
notes/1-主盘型/{盘型编号}-{盘型名}/5-语料设计.md
```

例：`notes/1-主盘型/02-次限盘/5-语料设计.md`

## 强制引用规则

1. **右侧面板的每张卡片的 summary 和 details 内容，必须映射到 `5-语料设计.md` 中对应的语料条目**。禁止从计算结果直接拼接占星术语作为用户可见文本。
2. **底部 Tab 的解读文本同理**，必须引用语料库中的对应章节。
3. **新增任何面向用户的文本**（包括阶段名称、主题描述、建议语句、组合句等），必须先在 `5-语料设计.md` 中补充对应语料条目，再在代码中引用。不允许"先写代码、后补语料"。
4. **专业参数 Tab 的数据展示**（如容许度、算法规则等）引用 `5-语料设计.md` 中的专业参数章节，不在代码中硬编码规则描述。

## 映射方式

代码中的 `build*` 函数应遵循以下映射流程：

```text
计算结果（星盘数据）
    → 查找对应的语料条目（按 point_id / sign / house / aspect type 索引）
    → 用语料模板填充实际参数（星座名、宫位号、相位类型等）
    → 输出用户可见文本
```

**禁止的写法**（直接拼接占星术语）：

```typescript
// 错误：硬编码关键词
cardADetails.push(`次限月亮在${signLabels[moonSign]}（${moonSignKeywords[moonSign]}）`);
```

**正确的写法**（从语料映射）：

```typescript
// 正确：从语料库数据结构中获取完整内容
const moonCorpus = secondaryCorpus.moonSignPhases[moonSign];
cardADetails.push(moonCorpus.summary);
```

## 语料数据结构化

### 文件位置

语料库 Markdown 中的条目，必须结构化导出为 TS 数据文件，位于：

```text
app/lib/insight/{盘型名}-corpus.ts
```

例：`app/lib/insight/secondary-corpus.ts`

### 数据结构

每条语料条目包含以下标准字段：

```typescript
type CorpusEntry = {
  id: string;           // 语料条目唯一标识，格式："{章节号}-{条目key}"
  keywords: string;     // 关键词（用于搜索和索引）
  summary: string;      // 一句话结论（右侧卡片 summary 用）
  detail: string;       // 展开描述（右侧卡片 details 用）
  challenge?: string;   // 挑战/注意事项
  advice?: string;      // 建议
};
```

各章节的语料以 `Record<string, CorpusEntry>` 形式导出，key 为索引键（如星座名 `scorpio`、宫位号 `8`、相位类型 `conjunction`）。

## 语料更新流程

1. **需求提出**：产品/内容团队在 `5-语料设计.md` 中新增或修改语料条目
2. **结构化导出**：开发人员将变更同步到对应的 `xxx-corpus.ts` 文件
3. **构建函数适配**：`build*` 函数改为从 corpus 文件读取，替换硬编码
4. **验证**：确认右侧面板和底部 Tab 的文本来自语料条目

**流程约束**：步骤 2 和 3 必须在同一 PR 中完成，不允许"语料已更新但代码还在硬编码"的中间状态。

## 版本同步

- `5-语料设计.md` 每次变更时，在文件顶部记录变更日期和变更摘要
- `xxx-corpus.ts` 顶部注释标注对应的语料库版本日期
- 代码审查时，对比 corpus 文件的版本日期与 `5-语料设计.md` 的最新修改日期，确认是否同步

## 检查清单

每次代码变更后，逐项确认：

- [ ] 右侧面板卡片中是否存在硬编码的中文解读语句（应替换为语料引用）
- [ ] 新增的面向用户的文本是否已在 `5-语料设计.md` 中有对应条目
- [ ] 底部 Tab 的解读内容是否引用了语料库对应章节
- [ ] `build*` 函数中是否存在硬编码映射（应替换为 corpus 文件引用）
- [ ] 专业参数 Tab 的规则描述是否来自语料库的专业参数章节
- [ ] corpus 文件的版本日期是否与 `5-语料设计.md` 最近修改日期一致
- [ ] 语料变更和代码变更是否在同一 PR 中完成
