# 验证规范

> 每次代码变更后必须通过验证，确认功能正确且无回退。

---

## 验证层级

### 第一层：编译验证

| 检查项 | 命令/方式 |
|---|---|
| TypeScript 类型检查 | `docker compose exec web npx tsc --noEmit` |
| 生产构建 | `docker compose build web` |
| 后端启动 | `docker compose up api` 后检查健康检查 |

**规则**：编译错误必须在提交前修复。

### 第二层：视觉验证（Playwright 截图）

**必须截图的场景**：

| 场景 | 视口 | 说明 |
|---|---|---|
| 桌面宽屏 | 1440×900 | 默认布局 |
| 手机 | 375×812 | 单列垂直堆叠 |
| 变更区域特写 | 按需 | 截取变更涉及的组件 |

**截图流程**：

1. 启动 Playwright，导航到对应页面
2. 执行计算/切换 Tab 等操作使变更内容可见
3. 分别截取宽屏和手机视口
4. 使用 `image_understanding` 工具验证截图内容：
   - 卡片是否渲染
   - 文字是否完整显示（无截断/溢出）
   - 布局是否正确（无重叠/错位）
   - 手机端是否垂直堆叠

**规则**：
- 右侧面板变更：必须截图验证
- CSS 变更：必须同时验证宽屏和手机
- 底部面板变更：截图整个底部区域
- 轮盘变更：截图轮盘区域

### 第三层：功能验证

| 检查项 | 验证方式 |
|---|---|
| 计算按钮 | 点击后结果正确渲染 |
| AI 按钮 | 点击后降级提示正确显示（未配置时） |
| Tab 切换 | 底部 Tab 切换内容正确 |
| 参数修改 | 修改参数后重新计算，结果更新 |
| 空状态 | 未计算时显示等待提示 |

### 第四层：回归验证

| 检查项 | 验证方式 |
|---|---|
| 本命盘 | 截图确认未受次限盘变更影响 |
| 行运盘 | 截图确认未受次限盘变更影响 |
| 其他已完成的盘型 | 逐一截图确认 |

**规则**：修改 `insight/shared.ts` 或 `styles/shared.css` 时，必须回归验证所有盘型。修改盘型专用文件时，只需回归验证该盘型。
