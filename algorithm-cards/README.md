# Interstellar 算法卡库

本目录保存进入实现前已经做出明确技术选择的算法卡。`catalog.yaml`是唯一索引；每张卡只描述一个`capability_id`，可以覆盖多个`calculation_id`。当前首批卡片统一为`status=review`、`implementation_status=not_started`：表示实现规格已经写全，可以启动隔离实现，但尚未通过双实现差异验证和主责复核。`approved`只在上述门禁完成后使用，仍不等于能力已经达到Stable。

## 全局约定

- 角度内部使用IEEE-754双精度十进制度；黄经规范化到`[0,360)`，有符号角差规范化到`(-180,180]`。
- 时间输入保存原始当地值，计算时使用UTC；需要TT/TDB时必须记录Delta T和转换来源。
- 默认星历为Swiss Ephemeris本地版本化文件，JPL SPICE只做独立差异验证。
- 任何默认值都来自版本化Preset，不得散落在前端或算法代码中。
- 搜索精确时刻统一采用“粗扫→区间包围→Brent求根”，并返回区间、容差和迭代信息。
- 所有结果必须写入Canonical Schema，保留算法版本、数据版本、参数、警告和空值语义。
- 金标准不使用商业报告文本；只保存合法可复用的输入、结构化预期结果、容差和来源。
- `review`允许按卡片启动实现，但不允许发布为Stable；`approved`必须已经完成独立参考实现差异验证与主责复核；实现后仍须经过单元、属性、金标准、差异和边界测试，成熟度才能提升。

## 评审模式

唯一责任主体为Interstellar主开发代理。子代理可以并行研究或实现；主代理必须逐卡检查公式、参数、Schema、测试和许可证，并在`catalog.yaml`记录复核哈希。外部评审是增强项，不是开发前置依赖。
